# Инструкция для агента: Android-проект «Навигатор Абитуриента»

Ты работаешь **только в этом репозитории** (`MobileAppCollegeStats`) — это **клиентское Android-приложение**. Backend, Scrapy и парсинг **вне scope** этого репозитория; приложение общается с API по REST.

---

## 1. Цель проекта

Мобильное приложение **«Навигатор Абитуриента»** для абитуриентов московских колледжей: каталог колледжей (государственные / частные / федеральные), специальности, места, условия поступления, поиск, документы, избранное, профиль с FAQ.

**Платформа:** Android  
**Язык:** Kotlin  
**IDE:** Android Studio  
**Архитектура:** MVVM (Model–View–ViewModel)  
**UI:** Jetpack Compose + Material 3 (предпочтительно; XML только если Compose невозможен без веской причины)  
**Язык интерфейса:** русский  

---

## 2. Текущее состояние репозитория

На момент старта в репозитории может быть **только** `.idea/` и git — **полноценного Android-модуля (`app/`, Gradle) может не быть**. Если модулей нет — **создай стандартный Android-проект** (Empty Activity или Bottom Navigation Activity) с Kotlin DSL и минимальным SDK **26+**, target SDK **34+**.

Не трогай и не коммить временные артефакты: `_tz_extract/`, `_tz.zip`.

| Запрещено | Почему |

## 4. Архитектура системы (контекст)

```
[Android App] --REST JSON--> [FastAPI Backend] --> [БД]
                                    ^
                                    |
                            [Scrapy / парсинг]
```

Приложение:
- запрашивает данные через **REST API** (JSON);
- при ошибке сети показывает **кэш** (Room);
- **избранное** хранит в **Room** или DataStore на устройстве.

Для разработки без готового backend используй **mock JSON** в `app/src/main/assets/` и/или `BuildConfig` с переключением `USE_MOCK = true`.

**Эмулятор + локальный API:** базовый URL `http://10.0.2.2:<port>/` (не `localhost`).

## 9. Функциональные требования по экранам

### 9.1 Splash
- Показывать при запуске, если идёт загрузка/обновление с сервера.
- Если есть актуальный кэш — переход на главный экран **без задержки** или ≤ **1 сек**.
- Индикатор загрузки; при ошибке — сообщение + кнопка **«Повторить»**.

### 9.2 Главная (Home)
- Три кнопки категорий → `CollegeListScreen(type)`.
- Опционально: краткая подсказка под кнопками.

### 9.3 Список колледжей (все три типа)
Карточка (`Card` / `LazyColumn`):
- название;
- краткое описание (специализации + кол-во мест);
- кнопка «Подробнее»;
- иконка **сердца** (избранное).

**Доп. поля по типу:**
| Тип | Дополнительно в деталях |
|-----|-------------------------|
| Государственные | базовый набор |
| Частные | стоимость обучения, рассрочка (если есть) |
| Федеральные | особые условия поступления, наличие общежития |

### 9.4 Деталь колледжа
- список специальностей;
- бюджетные и платные места;
- проходные баллы (если есть);
- краткая информация о поступлении;
- ссылка на официальный сайт (`Intent.ACTION_VIEW`);
- сердце у колледжа и у специальностей.

### 9.5 Избранное
- Тап по сердцу: добавить / удалить.
- Отдельный экран со всеми сохранёнными элементами.
- Хранение: **Room**, без авторизации.
- Заложить расширяемость (отдельная таблица с `entityType`: COLLEGE / SPECIALTY), но не реализовывать серверную синхронизацию.

### 9.6 Поиск
- По названию колледжа и специальности.
- Фильтры: бюджет/платное, проходной балл, расположение (район/локация — поле из модели).
- Результаты — список карточек как в каталоге.

### 9.7 Документы
- Статический контент и/или данные с API.
- PDF: открытие внешним viewer или WebView.
- Ссылки: `CustomTabs` или browser intent.

### 9.8 Профиль
- Пункт «Избранное» → экран избранного.
- «Настройки» — заглушка или базовые (тема/очистка кэша), без лишнего.
- **FAQ:** список вопросов, раскрытие ответа (аккордеон / `AnimatedVisibility`).

## 10. Модели данных (domain)

```kotlin
enum class CollegeType { STATE, PRIVATE, FEDERAL }

data class College(
    val id: Int,
    val name: String,
    val type: CollegeType,
    val shortDescription: String,
    val address: String?,
    val websiteUrl: String?,
    val specialties: List<Specialty>,
    // частные
    val tuitionCost: String?,
    val installmentAvailable: Boolean?,
    // федеральные
    val specialAdmissionConditions: String?,
    val hasDormitory: Boolean?,
)

data class Specialty(
    val id: Int,
    val name: String,
    val budgetPlaces: Int?,
    val paidPlaces: Int?,
    val passingScore: Int?,
    val admissionInfo: String?,
)
```

DTO в `data/dto/` — под формат API; маппер в domain.

## 11. API (контракт для Retrofit — согласовать с backend)

Базовый путь (настраивается в `BuildConfig.API_BASE_URL`):

| Метод | Endpoint | Назначение |
|-------|----------|------------|
| GET | `/colleges?type={state\|private\|federal}` | Список |
| GET | `/colleges/{id}` | Детали |
| GET | `/colleges/search?q=&budget=&minScore=&district=` | Поиск |
| GET | `/documents` | Документы |
| GET | `/faq` | FAQ (опционально) |

Пока API нет — `CollegeRepository` читает `assets/mock_colleges.json`.

**Кэш:** при успешном ответе сохранять в Room; при `IOException` — отдавать кэш и показать Snackbar «Показаны сохранённые данные».

## 13. Порядок реализации (выполнять последовательно)

1. **Скелет:** Gradle, `MainActivity`, тема (бордовый), `AndroidManifest` (`INTERNET`).
2. **Навигация:** bottom bar + пустые экраны-заглушки.
3. **Mock-данные** + `CollegeRepository` + список/деталь для одного типа.
4. **Все три типа** колледжей + различия полей в UI.
5. **Splash** + логика кэша/загрузки.
6. **Room:** избранное + сердца на списке и деталях.
7. **Поиск** + фильтры (на mock или API).
8. **Документы** + **Профиль/FAQ**.
9. **Подключение Retrofit** к реальному base URL (если дан пользователем).
10. Полировка: обработка ошибок, пустые состояния, accessibility (contentDescription на иконках).

После каждого крупного шага — проект **должен собираться** (`./gradlew assembleDebug`).
